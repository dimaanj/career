Путь задачи

Агенты готовят и проверяют, решает человек

решение человекаавтоматический контрольвозврат на доработку

Агенты не делают коммит, push и PR. Это решение и ответственность человека.

Под квадратами — 11 состояний оркестратора (конечный автомат§5): каждое печатает маркер [STATE: …], пропуск шага виден в аудите§8. Исполнение — через handoff§7, возвраты ограничены§11, одобрение и передача — решения человека§17.

Человек говорит только с оркестратором. Коммит и PR делает только человек.

«Нет инструмента» — граница задана набором tools агента: у исполнителей нет agent, у ревьюера нет edit. Оркестратор не правит код по правилу договора. Перед работой каждый агент читает инструкции репозитория (AGENTS.md, copilot-instructions.md). Номера § — разделы глоссария.

Приёмы

Восемь приёмов, на которых держится флоу

§7

Handoff

Исполнитель получает компактный JSON: репозитории, allowedFiles, риск, допущения.

Не пересказ диалога: меньше токенов, жёсткие рамки.

§27

Изоляция контекста

Каждый видит только своё: исполнитель — handoff, линза — дифф, верификатор — код.

Чужие выводы не влияют на мнение.

§12

Гейты

Скрипт с JSON-отчётом вместо «тесты прошли»: PASS / FAIL / SKIPPED.

Доказательство, а не утверждение.

§G

Отказ по умолчанию

SKIPPED ≠ PASS. Сомнение в риске — уровень выше. Нет инструментов — стоп.

Пробел в проверке не выглядит как успех.

§16

Риск задаёт глубину

low / normal / high определяют набор гейтов, ревью и бюджет.

Мелочь дешёвая, рискованное не проскочит.

§20

Независимый верификатор

Каждое замечание проверяет субагент, который его не писал.

Шум отсеян до человека.

§17

Человек решает

Утверждает план, принимает итог, делает коммит.

Результат флоу: готово к ревью, а не к PR.

Ревью

Каждое замечание ревьюера проходит независимую проверку

До человека доходят только подтверждённые замечания. Без ответа на важное задачу не сдать.

  • Четыре линзы§19 — параллельные субагенты ревьюера, каждый видит только дифф, REVIEW.md и свою линзу. Замечание без file:line и сценария сбоя отбрасывается.
  • Верификатор§20 — субагент, который замечание не писал: перечитывает код, а не рассуждение, и выносит CONFIRMED / UNCERTAIN / REFUTED. Дубли сливаются, серьёзность по единой шкале§21.
  • Журнал замечаний§22 — вердикт и ответ автора (fixed / dismissed / deferred). Пока на подтверждённое важное нет ответа, open-findings не даёт сдать задачу.
Стоимость

Модель работает только там, где без неё не обойтись

Скрипт вместо модели§3

Линтер, тесты, дифф контракта, скан секретов, подсчёт бюджета — без токенов.

Сильная модель — где смысл§24

Самая сильная — для логики, безопасности и верификатора. Для качества UI — дешевле.
